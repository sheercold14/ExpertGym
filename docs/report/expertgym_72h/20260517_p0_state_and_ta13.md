## 待填结论

- TA-1/3 确实具备三任务结构能力：Tool mean 0.7848、Memory mean F1 0.6465 已不是弱 base；但 `paper96` 下仍有大量 frontier，说明它适合观测 policy 可变性。
- TA-0.75/init1 让 Tool/Memory 大量进入 stable，但 Code 在 `paper96` 与 `eval-targeted96` 下都仍有 10-18 个 unsolved；这支持“强静态 scale 不是完整答案”，尤其 Code 需要更可执行、更对齐 CURE 的 calibration。
- eval-targeted96 相比 paper96 更能暴露 Tool live-like 与 Code 缺口：base 的 Tool 不再全错，但 TA-0.75/init1 的 Code unsolved 仍高，说明新 bank 应围绕 eval-like frontier/recoverable 采样，而不是只复用 paper96。
- best-ever TAME 作为外部强参考，在 Tool/Memory 上与 TA-0.75/init1 接近，但 Code 在 eval-targeted96 仍有 18 个 unsolved，说明当前 Code 短板不是单纯全局 scaling 可以消除；需要更好的 Code verifier-aligned OPD positive 和 selection/BoN calibration。
- GRPO-only 对 TA-1/3 有大量 frontier 信号，但对 TA-0.75/init1 会快速变稀疏；OPD/retention 的角色应随 state 分布动态变化。
- `paper96` 不能作为唯一主 bank：TA-1/3 下 stable 为 0，init1/TA-0.75 下 stable 又过多，且 Code recoverable/positive 仍不足。下一步需要依据 `docs/harness/calibration_design.md` 构造 `calib_bank_v1_20260518`。

## Calibration 审计结论

只读审计结论：下一版主 bank 不应直接沿用 `paper96`。`paper96` 适合作 baseline/anchor，因为它平衡、可复现、有旧 expert rollout；但它的 Tool 偏 ToolRL/RLLA，Code 不对齐 CURE，fixed OPD 不绑定当前失败，不能作为论文主方法的唯一 calibration。

72h 内更合理的 bank 是：

```text
/tmp/shared-storage/OnPolicy/data/calibration/calib_bank_v1_20260518/
  train96.prompts.jsonl
  monitor48.prompts.jsonl
  guard48.prompts.jsonl
  expert_rollouts/
  state_tables/
  summary.json
```

`train96` 用于反传；`monitor48` 用于 early stop / checkpoint selection；`guard48` 只用于最终 non-regression，不参与调参。
